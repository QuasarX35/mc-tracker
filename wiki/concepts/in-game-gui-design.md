# In-game GUI design

Emulating the look of a 2011-era Java game inside a browser. The lesson from implementing it
for the [[Minecraft Build Tracker]] is that authenticity comes almost entirely from **chrome
and geometry**, not from copying artwork: once the panel grey, the 2px bevel, the square corner
and the bitmap font are right, a flat CSS prototype already reads as Minecraft. Raw decisions:
[`raw/sources/2026-10-25-minecraft-gui-design-system.md`](../../raw/sources/2026-10-25-minecraft-gui-design-system.md).

## The load-bearing details

- **Panel grey `#c6c6c6`** with a **2px black outline** and an **exact 2px bevel**: white on
  top-left, `#555` on bottom-right. This single component does most of the work; a 1px or 3px
  bevel immediately looks wrong.
- **Square everything.** One `border-radius` anywhere breaks the illusion.
- **Inverted bevel for insets** (slots, pressed buttons): dark top-left, light bottom-right.
- **Bitmap type** at integer sizes, bundled locally; the shadow is a hard 2px offset, never a
  blur.
- **Slots and XP bars** are semantic objects in the game's visual vocabulary: a 30×30 inset
  square holding a 22 px item render (downscaled from the game's 256 px inventory render), and
  a green bar with a lighter top band.
- **Vanilla tooltip**: `#100010` plate with a `#5000ff` border — instantly recognisable.
- **A textured world behind the panel** (tiled dirt, darkened with a vignette) supplies the
  "in-game screen" framing that a flat colour cannot.

## Why CSS instead of a texture pack

Real GUI textures would need nine-slice scaling and hundreds of image files. Because the shapes
are simple rectangles with a fixed bevel, CSS reproduces them more faithfully at any size and
keeps the repository free of third-party art. Two exceptions need real pixels: the tiling
block textures are generated by us, and the **item icons are the game's own 256×256 inventory
renders**, exported locally from the owner's client and kept out of version control
([[Vanilla assets without redistribution]]). The tiled textures are 16×16 and scaled with
`image-rendering: pixelated`; the item renders are displayed with `image-rendering: auto`
because nearest-scaling a 256 px render into a 22 px slot aliases (EDICT-0011).

## Tensions

- **Contrast vs. fidelity.** Vanilla draws white text on light grey, which fails WCAG AA. The
  shipped system uses dark text on light panels and shadowed white text on dark rows. It looks
  right and it is readable; it is not pixel-identical ([[Minecraft Build Tracker]]).
- **Legibility at small sizes.** True Minecraft text at 8–10 px is unreadable on a modern
  display; the app uses 13–16 px pixel type instead.
- **Nostalgia is a moving target.** "Looks like Minecraft" spans 1.7 to 1.21, each with a
  different GUI palette. This system targets the grey-panel era deliberately.

## Real assets versus drawn ones

Hand-drawn approximations got the layout right but not the recognition: a familiar ingot or
cobblestone cube is what makes a slot read instantly. The shipped set therefore uses the
game's own **inventory renders** — 256×256 images from the game's item renderer, exported with
IconExporter — with the legal and technical machinery documented separately
([[Vanilla assets without redistribution]]). The renderer matters: an early extractor
composited cube icons from 16×16 textures by hand and the geometry was visibly off (skewed
logs, flat stand-ins for 3D items); the game's own projection fixed that and raised the
resolution in the same move. That 256 px source is then shown at UI sizes with smooth
downscaling — the one place the pixel-art "integer scale" rule is deliberately retired.

## Panorama backdrop

The menu's atmosphere is not the GUI chrome — it is the panorama behind it: six cube-face
screenshots of a world, blurred and slowly rotating. The app reproduces the treatment with four
stitched side faces, a baked Gaussian blur, a 120 s ping-pong pan and a scrim for text contrast,
and it freezes under `prefers-reduced-motion`. Crucially, the source is odd: the version jar's
`panorama_*.png` files are 1×1 placeholders; the real 1024×1024 faces live in the asset store and
are resolved through the asset index. Identity avatars sit at the other end of the same idea:
small, square, bevelled slots that make a world or build recognisable at a glance
([[Atmosphere and identity without shipping assets]]).
