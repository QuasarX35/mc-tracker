# Minecraft Build Tracker

A single-page tool that answers one question at a time while playing: *what do I still need to
finish this build?* Worlds contain builds and one shared inventory; builds contain materials; the
world's shopping list is what the builds still need after that inventory is allocated in build
order. It opens by double-clicking `src/index.html` — no build step, no server, no install
— and stores everything in the browser. Raw spec:
[`raw/sources/2026-10-25-minecraft-build-tracker-spec.md`](../../raw/sources/2026-10-25-minecraft-build-tracker-spec.md).

## What it does

- **Worlds** — one tracker per world, with edition and version; the active world is chosen in the
  left sidebar, which also carries its derived progress, the inactive-build display mode, the
  Items/Stacks/Shulkers switch and the shopping list. It is edited in the Worlds tab.
- **Builds** — name, status (Planned / Building / Done), coordinates, notes, and an XP-style
  progress bar driven by the material list.
- **Materials** — per build, an item name plus `needed`; the world holds a single inventory, and
  each build's `in`/`left` (and a surplus) is the result of allocating that stock in build order
  ([[Shared inventory]]). `needed` is a plain cell committed on Enter/blur, and every quantity
  change goes through one inventory dialog (absolute or `+64`/`-32`/`2s`/`2s+10`) with Undo.
- **Interaction pass (EDICT-0014)** — the icon picker pages all 1,368 items in 120-tile batches
  and leads with recent picks; a deterministic suggestion can propose an icon with a stated
  reason; a shared tooltip follows hovered slots inside dialogs; empty screens offer the next
  action; bulk paste parses a material list; deletions offer Undo for 6 s.
- **Shopping list** — the outstanding need after allocation across the world's active builds,
  largest shortfall first, with which builds need it, search, filter and copy-to-text.
- **Backup** — JSON export/import, validated before it replaces anything; schema 2 with a
  one-time migration of old per-build `collected` counts.

## How it is built

| Layer | Implementation |
|-------|----------------|
| Domain | `src/tracker/model.js` — pure immutable-update model; aggregation, validation, storage adapter, sample seed. Classic script so `file://` works (ES modules are blocked there). |
| UI | `src/index.html` + `src/app.js` — three tabs, inline editing (title/notes save on Enter, Needed commits on Enter/blur, typing never re-renders), dialogs, toasts, `aria-live` status. |
| Visual | `src/styles.css` — the [[In-game GUI design]] system: grey panels, 2px bevels, square corners, slots, XP bars. |
| Assets | 9 tiling textures + favicon generated by `scripts/gen-assets.py`; **1,368 item icons are the game's own item renders** — 256×256 inventory renders exported locally by `scripts/mc-icons.py` and never committed ([[Vanilla assets without redistribution]]); the Minecraft bitmap face with Pixelify Sans as the fallback. |
| Persistence | [[Local-first tracking]]: `localStorage` (`mc-build-tracker:v2`, schema 2) plus export/import; a v1 document is migrated once into the world inventory. |

## Why it looks the way it does

The first design pass followed an inherited neon dashboard system and was rejected by
direction: *"look as close to Minecraft's in-game UI as possible"*. The replacement is
documented in [[In-game GUI design]], and the reversal itself in
[[Vanilla GUI over a neon dashboard]].

## Icons

Icons are the real thing, within licensing limits. Since EDICT-0011 they are the game's own
**256×256 inventory renders**, exported from the owner's installation with IconExporter and
copied by `scripts/mc-icons.py` ([[In-game GUI design]]). That is the game's actual
inventory-renderer output — correct 3D item models and isometric blocks — rather than the
approximate 16×16 composites EDICT-0007 made by hand. The app downscales the renders smoothly
at 22 px in slots and 28–48 px in avatars; the tiled block textures stay nearest-neighbour
pixel art. The repository commits the extractor, a provenance manifest and a notice, never the
pixels; a machine without the export falls back to the 16×16 client-jar extraction, and the
manifest labels which mode was used. A machine without Minecraft installed still runs the app;
missing icons fall back to the item's initial.

**Catalog (EDICT-0013).** The set is no longer the curated 53 materials: the export is read
whole and collapsed to base items — **1,368 addressable icons** from 1,609 item renders (1,363
plain renders plus 246 component variants; the 246 collapse to 5 representatives, leaving 241
`collapsed_variants`), curated common items first. `icons.js` exposes `MC_ICON_SET`,
`MC_ICON_NAMES` (an object keyed by slug) and `MC_ICON_STACKS` (default 64; 16 for egg,
snowball, ender pearl, honey bottle, armour stand, empty bucket, signs and banners; 1 for filled
buckets, tools, armour, elytra, potions, boats, minecarts, shulker boxes, beds, cakes/stews,
books, maps, banner patterns and discs), and the manifest records name, stack, sha256 and
lighting per icon. Base-item granularity means a specific potion or painting variant is not
pickable; items the export lacks stay lettered.

**Brightness correction (EDICT-0012).** IconExporter 1.3.1 exports 3D (block-model) icons
roughly a third too dark: it scales the icon pose non-uniformly, which flattens Minecraft's GUI
diffuse lighting, while flat 2D sprites are unaffected ([[Vanilla assets without
redistribution]] records the upstream bug). The extractor therefore restores the vanilla
inventory face ratios — 0.99 top / 0.65 left / 0.40 right of the block texture — with a
per-face gain calibrated against the client jar, records the measured factors and gains in
`manifest.json`, and leaves flat sprites byte-identical; 3D props get the area-weighted gain.
After correction the median face fractions are 0.991 / 0.651 / 0.403 (≤1 % off the targets).
This is a compensation for a known exporter bug, not a re-render; when a fixed IconExporter for
1.21.4 ships, re-exporting should let the correction be dropped. EDICT-0013 migrated the
per-icon classification to the jar model chain — `block` (407), `flat` (620), `3d-other` (341),
no `none`; `hopper` is flat, `anvil` and `chest` are 3d-other and lit. Five flat sprites
(`enchanted_book`, `enchanted_golden_apple`, `end_crystal`, `experience_bottle`,
`nether_star`) are byte-for-byte copies with no correction and are disclosed as
`flat_pixel_mismatches`.

## Typography

EDICT-0013 replaced Pixelify Sans as the primary face with the game's own bitmap font:
`src/assets/fonts/Minecraft.ttf` (Craftron Gaming, via DaFont, "100% Free", 14,488 B; licence
file beside it and sealed raw provenance in
[`2026-10-25-minecraft-font-licence`](../../raw/sources/2026-10-25-minecraft-font-licence.md)).
It maps 107 codepoints — ASCII complete, U+20AC euro, a little Latin-1 — and has no accented
letters; arrows, dashes, ellipsis, `×`, `·`, `≥`, `≤` are absent and come from Pixelify Sans,
which stays the bundled fallback (`--font-pixel: "Minecraft", "Pixelify", ui-monospace,
monospace`). Lowercase renders as small capitals, which is the vanilla look; EDICT-0016 moved the
scale to body 18, muted 17, meta 15, tiny 13, with a 22 px dialog and the `clamp(40px, 7vw, 72px)`
title.

## Detail editing and native controls

EDICT-0013 also reworked the detail panel. The always-visible Name field is gone: a pencil
(`#build-rename`) sits left of Delete beside the title, and clicking it swaps the heading for the
existing `#build-name` input with Save/Cancel — Enter saves, Escape restores, blank titles are
refused and focus returns. Coordinates gained an icon-only copy button (`#copy-coords`, disabled
when empty or whitespace); notes display as escaped text (`#notes-text`) and only become a
textarea (`#build-notes`) while editing, with `Ctrl`/`Cmd`+`Enter` to save. Each material row is
now eight cells — Item, Needed, Got, In, Left, Surplus, Update, row menu — where Needed is the
only editable number, the middle columns are derived, and Update opens the shared inventory
dialog ([[Shared inventory]]). The six `button.mat-step` buttons, `data-step` and the `.stepper`
are retired by EDICT-0017. The icon picker is one dialog (search, grid, footer upload) instead of
Item/Image tabs; it pages 120 tiles at a time until all 1,368 are reachable, resets to the first
batch on a search change, leads with recent picks, and can mark a suggested icon with
`#icon-suggest-note`. Adding a material opens the same picker in pick-item mode (`#mat-choice`).
Dropdowns stay native `<select>`s and are themed through `@supports (appearance: base-select)`
and `::picker(select)` — panel `rgb(111, 111, 111)`, 2 px black border, Minecraft face — so the
themed popup exists only on Chromium 155+; other browsers keep the OS popup ([[In-game GUI
design]]).

## The interaction pass (EDICT-0014)

EDICT-0014 kept the 2011 chrome and replaced the browser defaults underneath it. The picker is
now an append-only list: 120 tiles first, a sentinel appends the next 120 as it scrolls, and the
count hint reads `showing N of 1368 — scroll for more` (narrowed to `showing N of M for "query"`
while searching) — no hard cap, every slug reachable. Item names wrap instead of ellipsing in
tiles, material rows and the chooser chip, so `chiseled_polished_blackstone` is readable at
390 px.

A single `#mc-tooltip` surface in the open `<dialog>` (or the body outside one) replaces the
pseudo-element tooltips that were clipped by `overflow`; it is positioned fixed, clamped to the
viewport and flips below when the slot is near the top. Empty screens are real states: five
containers with working actions (create a world, plan the first build, go to materials, add a
material, clear the filter) rather than a toast telling the user what failed.

Bulk paste turns a pasted list into material rows: parse quantity+name, show matched and unknown
review rows (`64 stone bricks`, `- 32 glass`, `20x oak log` all parse), then add the matched set
in one commit. Deletion offers **Undo** in the toast for six seconds and restores a deep-equal
snapshot; a later commit invalidates it. The last eight chosen items lead the unfiltered picker
via `mc-build-tracker:recent` in `localStorage`.

The suggestion is deterministic and local: `M.suggestIcon(build, world, catalog)` ranks keywords
from a frozen table over the build name, then notes and the world name, then the most-needed
material, then the world icon, and returns `{slug, name, reason}` or `null`. It never rewrites a
stored icon, the avatar shows it display-only (`data-icon-auto`), and choosing an icon sets
`iconAuto` false. The catalogue shape is deliberately mixed: `MC_ICON_SET` is an array of slug
strings while `MC_ICON_NAMES` and `MC_ICON_STACKS` are slug-keyed objects.

## The layout and identity pass (EDICT-0015)

EDICT-0015 attacked the friction that survived the interaction pass: the list, the header, the add
form, the guide rails and the scenery.

- **Ordering.** Builds render by status rank — Building → Planned → Done — stable within a rank,
  never by completion ratio ([[Status-ranked build ordering]]).
- **Header.** The redundant world card is gone; `#world-meta` carries identity only, while
  `#world-progress` (`"36% gathered"` on the demo fixture, derived from `M.worldSummary`),
  `#world-remaining` (`"1,452 of 2,252 items still to collect"`) and a 10 px `#world-bar` with a
  6 px fill replace it ([[Status-ranked build ordering]]).
- **Measured layout.** Labels pair with their own controls ±1 px at 1280×900 and 390×844; one
  control height per row; the 1280×900 page fits its 900 px budget exactly, and the 390×844 case
  measures 1,423 px against a ≤1,500 threshold, with only material lists allowed to scroll.
- **Custom materials.** Three additive registries (build, world, account) resolve nearest-first
  over the 1,368-icon catalogue, with stack 1–999 and an icon from the catalogue or an upload
  ([[Material registry]]). Creation is immutable, the schema stays 1, and v1 backups still import.
- **Faster entry.** The add form gains `+1/+10/+<stack>` (the stack button appears after an item
  is chosen), and an Import dialog (`accept=".json"`) adds drag-drop and paste paths next to the
  chooser — the chooser itself was hiding JSON because its first `accept` token was an
  unregistered MIME type.
- **Scenery.** One `.backdrop__layer` at 4:1 (`800vh` / `400vh auto`) drifts `translateX(-50%)`
  over 120 s, with `#backdrop-pause` as the WCAG 2.2.2 control; `prefers-reduced-motion: reduce`
  now defaults the layer to **paused** (the OS preference is respected) and the button or a stored
  `motion=play` opts in — the opposite of EDICT-0014's freeze.

## The density round (EDICT-0016)

The founder first withdrew EDICT-0016, then reinstated it on 2026-10-26 and chose the built
result: the fourteen-item visual-density and compact-view round ships. The app uses the enlarged
type scale (body 18, muted 17, meta 15, tiny 13), notes in view mode with the edit controls in the
section header, created/updated timestamps on worlds and builds, a world sidebar, aligned section
rules, and a compact builds view (standard/compact switch, one card per build, a material-matrix
tile that opened a per-tile dialog). The `−`/`+` stepper and the per-tile dialog that round also
added were retired by EDICT-0017. `QA_PASS, cycle 1` stands on the restored tree: 96 browser cases,
audit 186/186. The three interaction components have their own pages: [[Number stepper]],
[[Compact view]] and [[World sidebar]]. The
[game-icon coverage note](../../docs/backlog/game-icons.md) still records the icon gap.

## The shared-inventory round (EDICT-0017)

EDICT-0017 replaced per-build `got` counters with one world inventory and an allocation, and
redrew the material row around the result. The round is built around one question: *how much of
this stock is left for this build, given the other builds?*

- **One inventory.** `world.inventory[slug]` counts what the player holds; a material stores only
  `needed`. `M.allocate(world)` walks builds in array order, skips paused and Done builds, and
  lets each active build claim what it still needs, so the first build wins contested stock
  ([[Shared inventory]]).
- **Row.** Needed is a text cell (Enter/blur commits, Escape restores, clamps at 1); Got, In, Left
  and Surplus are read-only, with `+N surplus` only when positive and `shared with N builds` when
  the stock is split; Update opens the dialog.
- **Inventory dialog.** One `#inventory-dialog` for a build+item pair takes an absolute number or
  a delta (`+64`, `-32`, `2s`, `2s+10`), the delta winning; one write, one Undo; Escape writes
  nothing ([[Shared inventory]]).
- **Paste preview.** `#paste-preview` parses first, lists one row per line and the unreadable
  lines, and imports in one commit only when the whole batch matched.
- **Compact.** The matrix is remaining-first: each tile shows what is left and opens the same
  inventory dialog; no `#tile-dialog` exists ([[Compact view]]).
- **Sidebar.** Progress moved into the world sidebar as one `X / Y items gathered (Z%)` line with
  its bar; the Items/Stacks/Shulkers switch is display-only; `#inactive-mode` keeps paused builds
  in place, pushes them to the end or hides them; the rail collapses to 56 px and remembers
  ([[World sidebar]]).
- **Persistence.** Schema 2 under `mc-build-tracker:v2`, v1 key left untouched; migration sums each
  build's `collected` into the world inventory per item case-insensitively and then drops it — a
  one-time, one-way merge ([[Shared inventory]]).
- **Retired.** `.stepper`/`data-step`, `#bulk-dialog`, `#tile-dialog`/`#tile-*`, the
  `#world-remaining` count, the 264 px material-list cap and the 960 px desktop budget.

The [[Number stepper]] page documents a component this round removed; its keyboard story
(Shift = stack, Ctrl/⌘ = 16) survives only in the inventory dialog's `2s`/`2s+10` syntax.

## Identity

Every world and build carries one optional avatar (EDICT-0010): a Minecraft item icon from the
locally extracted set, or an uploaded picture. It appears in the world bar, world cards, build
rows and the build detail header; clearing it restores the subject's initial. Uploads are
centre-cropped to 128×128, encoded WebP/PNG and stored as data URLs inside the saved state, so
backups remain self-contained at the cost of browser storage. See
[[Atmosphere and identity without shipping assets]].

## Atmosphere

The dirt texture is the fallback. When the locally generated panorama exists, the app shows the
real title-screen scenery: six resolved panorama inputs, of which the four side faces are
stitched with a wrap crossfade (the top/bottom caps are recorded but not stitched), baked at a
Gaussian radius of **2.0** and composed into a 2,560×640 strip (55,096 B, sha256
`331253bd…bf1a5`). EDICT-0015 replaced the two-copy 180 s loop with a single 4:1 layer —
`width: 800vh; background-size: 400vh auto; repeat-x` — drifting `translateX(-50%) → 0` over
**120 s** linear infinite, with `#backdrop-pause` as the user-facing stop.
`prefers-reduced-motion: reduce` defaults the layer to paused with the frame painted (the OS
preference is respected), and the button or a stored `mc-build-tracker:motion = "play"` opts in;
the global reduced-motion reset excludes `.backdrop__layer` and the layer never gets
`animation: none`. A missing or blocked backdrop silently keeps the dirt texture; nothing errors.
The extractor resolves the client's asset index because the jar's panorama files are 1×1 decoys
(raw source:
[`2026-10-25-minecraft-panorama-provenance`](../../raw/sources/2026-10-25-minecraft-panorama-provenance.md)).

## Tensions

- **Local-only by design.** No accounts, no sync; one browser holds one dataset. Loss is
  prevented by discipline (Export), not by the system ([[Local-first tracking]]).
- **Coverage is whole-export at base-item granularity.** 1,368 addressable items; the 246
  potion/painting/etc. component renders collapse to 5 representatives (241 `collapsed_variants`),
  so a specific variant is not pickable, and items absent from the export stay lettered. Stack
  sizes are a curated table with a default of 64, so an item outside the exception table can get
  a plausible wrong increment ([[In-game GUI design]]).
- **The allocation is positional.** It is computed from the world stock on every render, in list
  order, and never stored: editing the inventory changes every build's In/Left, and dragging a
  build changes who gets contested stock ([[Shared inventory]]).
- **Migration merges per-build counts.** Two builds that each recorded 64 stone become one world
  stock of 128; per-build attribution is lost by design and cannot be recovered from the migrated
  document ([[Shared inventory]]).
- **The bitmap face is licensed freeware with partial coverage.** `Minecraft.ttf` (Craftron
  Gaming, DaFont "100% Free") maps 107 codepoints; the licence text and a sealed raw source travel
  with it, and Pixelify Sans covers the missing glyphs. Copy that needs arrows, dashes, `×`, `·`,
  `≥`, `≤` silently mixes two faces.
- **Themed dropdowns are Chromium-only.** `appearance: base-select` + `::picker(select)` gives
  the themed popup on Chrome 155; other browsers keep the OS popup, and the design contract
  accepts that split rather than rewriting `<select>` in JavaScript ([[In-game GUI design]]).
- **Backdrop taste has a direction but not a measurement.** EDICT-0013 set the sharper bake,
  EDICT-0014 the seamless geometry and EDICT-0015 the single-layer 120 s drift with its pause
  control (six inputs, four stitched sides, 2,560×640, bake 2.0); the physical-display comparison
  with the real title screen remains open
  ([[Atmosphere and identity without shipping assets]]).
- **Custom items are additive and create-only.** Three registries resolve nearest-first over the
  catalogue; a custom name can shadow a catalogue name or a wider scope silently, editing and
  deletion are deferred, and existing free-text materials are not migrated
  ([[Material registry]]).
- **Motion policy is inverted from EDICT-0014.** `prefers-reduced-motion: reduce` now defaults the
  scenery to paused instead of freezing every animation; `#backdrop-pause` or a stored
  `motion=play` is the explicit opt-in, and the pause state survives reload while the paused frame
  re-samples at phase 0. WCAG 2.2.2 is met by the control, not by the media query alone.
- **The import chooser is system-dependent.** `accept=".json"` fixes the local registration, but
  the paste and drop paths exist because no OS chooser can be trusted to list a file; the native
  dialog itself is not screenshottable.
- **Alignment and height are measured at two viewports only** (1280×900 and 390×844), against an
  injected 4-build/6-material fixture; a long builds list still scrolls and other widths or zoom
  levels are unasserted.
- **Round-3 deferrals.** Custom-item editing/deletion, per-build stack overrides, bulk undo,
  a restore summary and a dialog-wide keyboard contract remain open
  ([UX backlog](../../docs/backlog/ux.md)); drag reordering shipped in EDICT-0017.

- **The suggestion is a heuristic, not a model.** `suggestIcon` ranks a frozen keyword table over
  the build name, notes, world name and material list and explains its pick; it can be wrong and
  it never overwrites a stored icon. The fixture table is the contract, so coverage beyond the 23
  frozen builds is unproven ([[Open questions]]).
- **Undo is a six-second snapshot.** One level, invalidated by any later commit; the toast carries
  the action (and replaces whatever text it had), so two deletions in a row offer only the last
  ([[In-game GUI design]]).
- **Paging is scroll-only discovery.** All 1,368 items are reachable, but there is no virtualised
  jump-to-letter and the count hint is the only progress signal; the suggestion and recents are
  the compensations ([[Open questions]]).
- **The catalogue has three shapes.** `MC_ICON_SET` is an array of slugs, `MC_ICON_NAMES` and
  `MC_ICON_STACKS` are slug-keyed objects; consumers that assume one shape for all three break
  ([[Vanilla assets without redistribution]]).
- **High resolution vs. pixel purity.** The old system claimed "item icons only at integer
  scale"; 256 px renders shown at 22 px cannot honour that, so item icons are smoothly
  downscaled while tiled textures stay nearest-neighbour. The gain is authentic 3D item models
  and HiDPI sharpness; the cost is a scoped exception in the design system ([[In-game GUI design]]).
- **Authentic pixels vs. a known exporter bug.** The 3D renders were exported darker than the
  game's own inventory because of an IconExporter 1.3.1 lighting bug; the tracker compensates
  the brightness offline rather than re-rendering. The pixels are therefore "the game's
  projection with restored vanilla lighting ratios", not untouched exporter output — disclosed
  in the manifest and `PROVENANCE.md`. A fixed exporter release would remove the caveat
  ([[Open questions]]).
- **Authenticity vs. legibility.** A pixel-faithful clone of vanilla's white-on-grey text
  fails WCAG AA; the shipped compromise favours reading ([[In-game GUI design]]).
- **Uploaded avatars live in browser storage.** 128×128 data URLs keep them small, but many
  uploads grow backups and count against `localStorage` ([[Local-first tracking]]).
- **Atmosphere depends on local extraction.** The menu backdrop is generated from the owner's
  client and git-ignored; without that step the app falls back to dirt ([[In-game GUI design]]).
- **Mobile is emulated, not physical.** The 390 px case uses CDP viewport override (a real
  390 px layout) but no phone, touch or OS file dialog is exercised. See [[Testing a UI like a user]].
